# 07 — Testing strategy

## Layers

| Layer | Where | Tooling |
|---|---|---|
| Unit | `#[cfg(test)] mod tests` next to the code | std, `insta` for complex values |
| Rule fixtures | `crates/pulse-rules/tests/fixtures/<RULE-ID>/` + one harness `tests/fixtures.rs` | harness below |
| Reporter snapshots | `crates/pulse-report/tests/` | `insta` (`assert_snapshot!`) |
| CLI end-to-end | `crates/pulse-cli/tests/` over `tests/fixtures/repos/*` | `assert_cmd`, `predicates`, `insta` |
| Performance | `crates/pulse-engine/benches/`, `scripts/bench.sh` | `divan`, `hyperfine` (optional) |

## Rule fixture harness

Layout per rule:

```
crates/pulse-rules/tests/fixtures/AI-SEC-002/
  fail_basic.md            # MUST produce >= 1 finding of AI-SEC-002
  fail_basic.md.expect     # optional: expected "line:col" per line, exact set match
  fail_obfuscated.md
  pass_code_example.md     # MUST produce 0 findings of AI-SEC-002
  _kind                    # optional: file containing the AssetKind to use (default: inferred from extension/name; see below)
```

- The harness iterates every fixture directory, builds an `Asset` with the kind from `_kind` (or inferred: `.md` → Instructions, `.mdc` → ScopedInstructions, `SKILL.md` → Skill, `.json` → McpConfig unless `_kind` says otherwise), and runs **only** the rule named by the directory (asset rules and project rules; for project rules every file in the directory forms the project).
- Failures print `fixture, expected, actual` compactly.
- The harness also asserts that every registered rule has a fixture dir with ≥ 1 `fail_*` and ≥ 1 `pass_*`, and a `docs/rules/<ID>.md`. Unimplemented rules are not registered, so this stays green phase by phase.
- Fixtures containing invisible characters are generated by the test (`\u{202E}` in Rust strings), not committed raw, so editors and git tooling don't mangle them. Put those cases in unit tests or in `fixtures.rs` helper cases. When every fail case of a rule is generated, a `_generated` file in its fixture dir (naming the tests) stands in for the `fail_*` requirement.

## Snapshot policy

`insta` snapshots are reviewed, not blindly accepted: after `cargo insta test`, read each `.snap.new` diff and accept only if it matches the spec. Never run `cargo insta accept` without reading the pending snapshots.

## Performance checks

- `divan` benches: estimator throughput, normalize throughput, full `scan()` over the `tests/fixtures/repos/large` generator (synthesized at bench time: 1,000 assets).
- `scripts/bench.sh` builds release and times `pulse scan` on fixture repos (hyperfine if available, else a loop with `/usr/bin/time`). It fails if the budgets in `00-overview.md` are exceeded by > 20%.
